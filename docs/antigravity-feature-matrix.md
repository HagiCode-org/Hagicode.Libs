# Antigravity CLI feature matrix

Records, for every `AgentCliFeatureCatalog` feature, what the Antigravity CLI (`agy`) actually does and the test that proves it. The backend preset may declare a feature only when its row here is **supported** or **partial** with a passing proving test (design D1a). A feature that is **not supported**, or still **pending**, stays undeclared.

- CLI version verified against: `agy 1.5.17` (`agy --version`), Linux, `~/.local/bin/agy`.
- Transport: ACP over stdio, `agy acp --stdio` (see the Antigravity CLI probe in `src/HagiCode.Libs.Providers/README.md`).
- Sign-in state of the verifying machine: **signed in**. An earlier probe on 2026-11-25 got the license reply (#3501) on every model turn. The real-CLI runs later that day did not show it, and the model turns returned output.

## Verdict status

Verdicts as of 2026-11-25 (agy 1.5.17). The user asked the implementer to decide every verdict from evidence, so the implementer decided them; the rows below carry the evidence.

- **Supported:** `chat`, `resume`, `steer`, `image` (2026-11-26: image attachments are sent as inline ACP image blocks, see gap G4).
- **Partial, declared:** `ask_user_question` (structured `ask_question` only; text-only questions are not answered by the handler).
- **Partial, not declared:** `magpie` (the model-list half is verified on the real CLI; the gateway-config half has no repeatable test, and the gateway route was checked by hand only).
- **Supported, declared (2026-11-25 update):** `built_in_skills` (loaded through `--add-dir` from a folder holding `.agents/skills`; gap G6 closed; the full Hero run is still open, see task 3A.7), `task_agent_family` (`antigravity` is in `PresetTaskAgentFamilies`; gap G8 closed).

The real-CLI tests were run twice on 2026-11-25 (agy 1.5.17, `HAGICODE_REAL_CLI_TESTS=1`, after `agy` was signed in). The first run and the second run had the same results, except for the structured-ask test noted under `ask_user_question`. The full Libs real run passed 74 of 74 once. A passing real test alone is not a verdict: each verdict also needs its declared scope to match the behaviour the test proves.

Hermetic tests (no switch) run in the default `dotnet test` profile. They use a synthetic scripted ACP agent, so they prove what HagiCode does on the wire and do not prove what agy does. The real tests (`[Category("RealCli")]`, `[Category("External")]`) skip with a reason unless the switch and `agy` are present.

## Probes for steer and ask_user_question (2026-11-25, agy 1.5.17)

Scratch probes over raw ACP stdio, timed, with every frame logged. They sit outside the repo (scratchpad `agy-probe/`), so the findings are recorded here and in gaps G3 and G5.

- **Steer** (steer sent after the first streamed chunk, prompt A "count 1 to 200", prompt B "answer only BLUE"): prompt A got `end_turn` at the moment prompt B was sent, with about one chunk before that. The rest of the output (1 to 200, then `BLUE`) streamed after that point and was attributed to prompt B, which ended later with `end_turn`. The steer did not interrupt the counting: BLUE came after 200. So agy accepts the steer into the running answer, but it closes the running prompt early and the client has to keep reading under the steer prompt. A steer is delivered; it is not an immediate interrupt.
- **Ask** (prompt: ask one clarifying question about favourite colour, then wait): in one run agy sent a `tool_call` named `ask_question` (kind `other`, `rawInput` holding the question and its options, status `in_progress` then `pending`) and the question as message text. In another run the question came only as message text, with no tool call. Both runs ended with `end_turn` and sent no agent request, so agy does not wait over ACP for an answer. A second prompt `Blue.` on the same session got "Got it—blue!", so the answer goes back as the next turn and the context is kept.
- **Model selection over ACP:** `session/new` advertises ten models and no magpie or Haiku entry. `session/set_config_option` and `session/set_model` both reject `magpie/claude/claude-haiku-5-5` and `claude-haiku-5-5` with `-32602 Unknown model ID`. Haiku 5.5 is reachable only through magpie's gateway (`magpie antigravity auto/claude-haiku-5-5`, which writes `~/.antigravity/settings.json` and needs an agy restart). Reverted after the test with `magpie antigravity default`.
- **Haiku 5.5 repeat** (magpie gateway, session model `auto/claude-haiku-5-5:medium`): steer gives the same result as Gemini. Prompt A ends with `end_turn` at the steer, and the count runs to 200 and then BLUE. The question comes as plain message text (no `tool_call`) and the turn ends with `end_turn`. The answer `Blue.` as a new prompt gets "Thanks, blue it is." So the steer and ask behaviour does not depend on the model.
- **Print mode without ACP** (`agy --input-format stream-json --output-format stream-json --print=`, Gemini default model): a usable non-ACP route, so ACP is not required. The stdin envelope is `{"event":"user","message":{"role":"user","content":"<text>"}}`; the output is `init`, `step_update` (`user_input`, `agent_response` with `text_delta`) and `result`. Steer here is **queued**: a second user message sent during a running answer is not applied to it. It runs as its own turn after the first one finishes (the first answer counted to 200, then BLUE). Ask is text-only: the question ends the turn with `SUCCESS` and the answer `Blue.` as the next user message gets a reply that uses it. So print mode gives the same verdicts as ACP: steer is delivered late, and ask is turn-based. Resume through `--conversation` and permission prompts in this mode were not tested.
- **Consumption** (`agy -p "/usage"`, no model turn): Gemini models at 63% of the weekly limit remaining, resets 2026-12-02 20:15 UTC; Claude and GPT models at 100%. The `usage_update` frames report context-window use (`used` of `size` 1,048,576), not billing or quota.

Conclusion for the verdicts: steer is supported over ACP (second `session/prompt` on the running session; the run waits for it). Ask is partial: the answer path works, but agy asks through the `ask_question` tool only some of the time, and a text question is not handed to the handler. Ask is declared as partial: `AntigravityGrain` creates a question broker for an interactive run (the same policy as Codex and OpenCode), forwards the structured question as a `Question` response, and delivers the answer through `AnswerUserQuestionAsync`. A text-only question is not covered by the declaration.

## Hero session check (6.1 and 6.2, 2026-11-25, agy 1.5.17)

Run against an isolated backend (scratch HOME and data, port 53359, scrubbed env, no dev-a or local-0 data). Read-only RPCs and writes were done through the backend's own gRPC-web and SignalR endpoints. The backend and every agy process were stopped afterwards.

- **6.1 identity (pass):** `GET /api/health/agent-cli/antigravity` returns `Healthy`, `providerType: AntigravityCli`, `displayOrder: 64`, resolved `agy`. The dual-monitoring payload includes the channel. `hagicode.hero.v1.HeroSettingsService/GetHeroSystemSettings` (served by `hagicode.platform.v1.SystemService`) lists `profession-antigravity` with family `antigravity`, `AntigravityCli`, executable `agy`, version `1.5.17`, features `chat, resume, ask_user_question, steer`, and reason `no_startup_mechanism`.
- **chat (pass):** a Hero session bound to an Antigravity hero replied `GREEN`. `isError` was false. Streaming fragments (`message.streaming.v1`) reached the SignalR subscriber.
- **cancel (pass):** a long turn went busy, `CancelSession` returned OK, the turn went idle, and the agy process that was alive before the cancel was gone after it.
- **steer (open, not passed):** an earlier note called this a pass, but the `BLUE` it found was the steer message's own text, and that steer had been queued as the next message. Two causes: (1) `SessionGrain.Steer.cs` `CanTakeSteerNow` did not list `AntigravityCli`, so every Antigravity steer was queued. **Fixed 2026-11-25**, pinned by `SessionCancellationStateTests.Steer_IntoAnActiveAntigravityRun_IsAcceptedByTheExecutor`. (2) After the fix the steer reaches the running agy (recorded as delivered). agy then did not answer the steered prompt: its ACP log shows `RESOURCE_EXHAUSTED` (HTTP 429, "Individual quota reached") at 18:41:05, and `agy -p "/usage"` shows Gemini weekly quota at 0% (resets 2026-12-02). The magpie Haiku route returns the same 429, so no steer reply can be produced until the reset. A real steer re-test is still needed after the reset. (3) Found and fixed in the Libs provider: when the steered prompt failed after the first turn had ended, the run closed as `terminal.completed` and the failure stayed hidden. It now reports `terminal.failed` (`AntigravityProvider.cs`, `AntigravityPromptRun.LatestFailure`), pinned by `AntigravitySteerFailureFeatureTests`.
- **resume (pass):** in a new session, turn 1 stored `ORCHID`. Turn 2 ran with `resumeMode: resumed` and `requestedSessionId` set, and its reply contained `ORCHID`.
- **ask_user_question (fixed 2026-11-25, see G10; re-run on the isolated backend after the fix):** the earlier failure was the prompt "ask me one clarifying question about my favourite colour (Red or Blue)" ran in `Readonly` and in `Edit` mode. In both, agy raised an `AskUserQuestion` tool call with status `pending` and the turn stayed busy for more than 4 minutes. The answer went through SignalR `AnswerSessionQuestion` and returned `outcome: resumed, state: answered`, but the backend logged `resolved as "resumed"` and queued the answer as a new message. The queued message started another run, and that run also stalled on a pending question. `CancelSession` cleared each stalled run. `AnswerSessionQuestion` on the gRPC service is unimplemented (only the SignalR hub answers questions).

## Gaps (2A.8 and the feature rows)

Each gap below is pinned by a test, so changing the behaviour fails that test. Update the matrix and the test together.

- **G1 Permission answers are not the user's choice.** Libs passes no permission handler, so `AcpJsonRpcClient` answers with the default `allow_always`. The agy docs say the client shows Allow or Deny. Pinned by `AntigravityCliBehaviourTests.Permission_request_is_answered_on_the_wire_with_the_default_allow_always_option`.
- **G2 Cancel sends no `session/cancel`.** A caller cancel ends the local stream only. The ACP v1 cancel path (`stopReason: cancelled`) is handled when agy sends it, but HagiCode never asks. Pinned by `AntigravityChatFeatureTests.Caller_cancellation_sends_no_session_cancel_yet_known_gap`.
- **G3 A question does not block the turn.** The question is visible to the client (a `tool_call` named `ask_question`, or message text), but the turn ends with `end_turn`. The provider answers a structured question by sending the answer as the next prompt (`AntigravityProvider`, `UserInputHandler`). A text-only question gets no answer from the handler. The real test `Real_agent_asks_a_question_and_the_client_sees_it` checks both forms. Any agent request other than `session/request_permission` is answered with -32601 and dropped (pinned by `AntigravityAskUserQuestionFeatureTests.Unknown_agent_request_is_not_surfaced_to_the_caller_as_a_question`). The placeholder method name is not a real agy method.
- **G4 (closed 2026-11-26) No image input in the provider.** `AntigravityProvider` now takes `AntigravityOptions.ImageAttachments` and sends each image as an inline ACP image block after the text block of the first prompt when the connection advertises `promptCapabilities.image`; images that fail validation (media type, size, count) or a connection without the capability are listed in the prompt text and reported in an `image.delivery` message. Pinned by `AntigravityImageFeatureTests.Provider_sends_an_attached_image_as_an_inline_block_after_the_text` and the planner tests.
- **G5 Steer closes the first prompt early (closed).** On agy the first prompt ends with `end_turn` when a steer arrives (see Probes). The provider keeps the run open until the steered prompt completes (`AntigravityPromptRun`); a completion notification is only a turn boundary while another prompt is open. Pinned by `AntigravitySteerFeatureTests.Steer_is_sent_as_a_second_prompt_and_the_run_ends_only_after_the_steered_prompt` and `Provider_sends_exactly_one_prompt_per_execution_so_it_never_steers_on_its_own`.
- **G6 No skill input (closed 2026-11-25).** `session/new` still carries only `cwd`, `mcpServers` and a null `settings`, but skills do not need a session field: agy loads `<dir>/.agents/skills` for the working directory and for each top-level `--add-dir <dir>`. `AntigravityOptions.AdditionalDirectories` now feeds `--add-dir` before `acp`. Pinned by `AntigravityBuiltInSkillsFeatureTests.BuildCommandArguments_passes_each_added_directory_with_add_dir_before_acp` and the `Session_new_carries_only_cwd_mcp_servers_and_settings...` test.
- **G7 Exit code lost on an early exit.** If the process has exited before the first write, the write fails with an `IOException` and the exit code is not carried. The test only requires that the turn fails (`Process_that_exits_before_reading_input_still_fails_the_turn`).
- **G8 `antigravity` was not a task-agent family in hagicode-core (closed 2026-11-25).** `PresetTaskRequirementModels.cs` now has `PresetTaskAgentFamilies.Antigravity = "antigravity"` in `SupportedFamilies` and `Resolve`, and the preset, the contract and the web registry declare it. The earlier "not supported" verdict depended on G6, which is now closed.
- **G11 Built-in skills need a web sentence (open).** The preset's `BuiltInSkillsReasonCode` is `prepared_skill_dir`. The web reason map does not have it yet, so the indicator shows no reason sentence for Antigravity. `prepared_plugin_dir` (omp) is missing there too.
- **G12 Mobile family map disagrees with the contract (open, not reverted).** An uncommitted edit in `repos/web/mobile/src/lib/hagitask-form.ts` removes `AntigravityCli` from `EXECUTOR_AGENT_FAMILY`, and its test expects `null`. The contract now says `antigravity`, so `agent-cli-contract.test.ts` in mobile fails. The owner needs to decide which side is right.
- **G10 Ask stalls in a Hero session (found 2026-11-25; fixed 2026-11-25).** The answer was sent as a new message because the Antigravity executor adapter did not implement `IExecutorStreamGrain`, so the interface default returned `NotSupported` and the grain was never called. Fix: `AntigravityExecutorStreamGrainAdapter` now declares `IExecutorStreamGrain` (`ExecutorStreamGrainAdapter.cs`). Pinned by `AntigravityExecutorForwardingTests`. On the isolated backend the answer then returned `Delivered` and agy answered `Red`. Still unverified: the same ask through a Local-0 build (Local-0 is not running).
- **G9 Partial license phrase.** The license rule (`AntigravityAcpMessageMapper.LicenseRejectionPhrase`) matches case-insensitively, across streamed chunks and in the prompt result. A first chunk that is only a prefix of the phrase is streamed as text before the match completes (pinned by `AntigravityChatFeatureTests.License_reply_split_across_chunks_...`). This rule is now only a guard: the 2026-11-25 real run did not show the reply.

## Fixes made 2026-11-25 (found while re-running the real tests)

- **Exit code lost on a fast exit (`SubprocessAcpTransport.ReceiveMessagesAsync`).** At stdout EOF the transport checked `HasExited` at once. If the OS had not yet reported the exit, it ended the stream silently, and the caller waited for the 45 s startup timeout. It now waits up to 2 s for the exit before deciding, so the stderr and exit code are reported. This is shared by every ACP provider.
- **Notifications dropped on a cancelled or failed turn (`AntigravityProvider.CancelReceiveLoopWhenPromptCompletesAsync`).** For any stop reason other than `end_turn`, the receive loop was cancelled as soon as the prompt returned, so chunks still queued (the partial text of a cancelled turn) were lost. It now waits 500 ms before cancelling. `Cancelled_stop_reason_becomes_a_terminal_failure_with_the_partial_text_kept` depends on this.

## Update rule

When a real run is recorded, replace the pending row with the verdict, the evidence (session transcript path or fixture name), and the test that now passes. Record the `agy` version for each verdict, and rerun the real-CLI tests whenever the version changes.
